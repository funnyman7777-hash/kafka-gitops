# Kafka GitOps Repository

This repository contains all manifests required to deploy a Strimzi‑Kafka platform with TLS and OAuth authentication using Keycloak, Vault and External‑Secrets.

## Architecture Overview
- **Vault** (dev mode) – stores TLS CA certificates and PKI for broker encryption, and secrets for Keycloak client.
- **External‑Secrets** – synchronises secrets from Vault into Kubernetes `Secret` resources.
- **Keycloak** – provides OAuth token endpoint for `SASL_OAUTHBEARER` authentication.
- **Strimzi Operator** – manages Kafka and Zookeeper clusters.
- **Kafka Cluster** – 4‑broker deployment with TLS listener and OAuth authentication.
- **Argo CD** – continuously reconciles the manifests from this repository.

## Scaling Guidance
- Increase `replicas` in the `Kafka` CR to scale the broker cluster.
- Adjust PVC `size` and `storageClass` for larger data volumes.
- Monitor CPU/Memory usage via Prometheus/Grafana and adjust the above limits accordingly.

## Troubleshooting
- **Argo CD sync failures** – check `argocd app get <app>` and ensure the repo URL uses SSH.
- **SealedSecret not created** – verify the Sealed Secrets controller is running and the public key matches.
- **TLS errors** – ensure the CA secret name matches the one referenced in the `Kafka` CR.
- **OAuth auth failures** – confirm the Keycloak client secret is correctly synced and the token endpoint URL is reachable from broker pods.
