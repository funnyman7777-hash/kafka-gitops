## 📋 Notes

- **Keycloak Issue:** Keycloak pods are failing to start due to ImagePullBackOff error for `docker.io/bitnami/keycloak:26.3.3-debian-12-r0`. This is a network connectivity issue preventing pulls from Docker Hub. Keycloak is required for OAuth authentication in Kafka.

  **Workaround Options:**
  1. Fix network connectivity to Docker Hub
  2. Use a different Keycloak version that exists in Docker Hub
  3. Pre-pull the image on the node and use imagePullPolicy: IfNotPresent
  4. Skip OAuth configuration and use scram-sha-512 authentication instead

- **Kafka Authentication:** The Kafka CR uses `scram-sha-512` authentication for the TLS listener (port 9093). The plain listener (port 9092) has no authentication. OAuth configuration requires Keycloak to be running first.

- **ExternalSecret Sync:** Fixed by updating ExternalSecret path to match Vault KV v2 structure. Duplicate ExternalSecret deleted from strimzi namespace.

- **Argo CD:** Admin password is `3GNwJAJAZOGChLzn`. Argo CD is running and managing the deployment.

- **Kafka Version:** Kafka 4.3.1 is running with 4 brokers and 3 controllers.

- **TLS Configuration:** TLS is enabled for both plain and TLS listeners. TLS secrets are mounted in broker pods via the my-cluster-broker-* secrets.

- **Kafka Test Status:** Kafka cluster is accessible at `my-cluster-kafka-bootstrap.kafka.svc:9093` (TLS) and `my-cluster-kafka-bootstrap.kafka.svc:9092` (plain). Testing with scram-sha-512 authentication requires creating a KafkaUser resource first.

### Test Commands (for future use)
```bash
# Get CA certificate
kubectl get secret my-cluster-cluster-ca-cert -n kafka -o jsonpath='{.data.ca\.crt}' | base64 -d > /tmp/ca.crt

# List topics (requires authentication or plain listener)
/tmp/kafka_2.13-4.3.1/bin/kafka-topics.sh --bootstrap-server my-cluster-kafka-bootstrap.kafka.svc:9092 --list

# Create a KafkaUser for scram-sha-512 authentication
kubectl apply -f - <<EOF
apiVersion: kafka.strimzi.io/v1beta2
kind: KafkaUser
metadata:
  name: my-user
  namespace: kafka
  labels:
    strimzi.io/cluster: my-cluster
spec:
  authentication:
    type: scram-sha-512
  authorization:
    type: simple
    acls:
      - resource:
          type: topic
          name: test-topic
          patternType: literal
        operation: Read
      - resource:
          type: topic
          name: test-topic
          patternType: literal
        operation: Write
      - resource:
          type: group
          name: my-group
          patternType: literal
        operation: Read
EOF
```
